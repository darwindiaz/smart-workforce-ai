# ADR-001 - Adoptar Monolito Modular como arquitectura inicial

## Estado

Aceptado

## Contexto

El proyecto Smart Workforce AI inicia como un MVP orientado a validar procesos de conciliación bancaria. Aunque la visión a largo plazo contempla una arquitectura basada en microservicios, adoptar dicho modelo desde el inicio incrementaría significativamente la complejidad operativa, el esfuerzo de despliegue, la observabilidad y la coordinación entre equipos.

Se requiere una arquitectura que permita desarrollar rápidamente el producto sin comprometer su evolución futura.

## Decisión

Se adopta una arquitectura de Monolito Modular.

Cada Bounded Context será implementado como un módulo independiente, manteniendo aislamiento funcional, límites de dominio claramente definidos y comunicación mediante contratos y eventos.

## Consecuencias

### Positivas

- Menor complejidad inicial.
- Desarrollo más rápido del MVP.
- Despliegue simplificado.
- Menor costo operativo.
- Facilita pruebas de integración.
- Base sólida para evolucionar hacia microservicios.

### Negativas

- Escalamiento inicial compartido.
- Una única aplicación desplegable.
- Mayor disciplina para mantener el desacoplamiento entre módulos.

## Alternativas consideradas

### Microservicios desde el inicio

**Descartada** por incrementar la complejidad sin aportar beneficios proporcionales durante la fase inicial del producto.

### Monolito tradicional

**Descartada** porque dificulta la evolución del dominio y favorece el acoplamiento entre módulos.
